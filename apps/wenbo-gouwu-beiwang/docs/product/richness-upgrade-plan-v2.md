# 购物备忘 · App 丰富度升级方案（v2 · 面向华为 3.7）

> 版本基线：1.2.0（已实现情景工作台、成长体系、主题/计划/收藏/洞察）  
> 目标版本：1.3.0 + 1.4.0 分阶段  
> 原则：**渐进增强，不推倒重做；0 新增系统权限**

---

## 1. 产品重新定位

### 从（审核眼中的现状）

「简易购物清单 + 备忘」—— 与市面大量 Todo/清单 App 同质。

### 到（上架叙事与真实能力）

**「个人与家庭采购工作台」** —— 围绕「规划 → 执行 → 核对 → 记账 → 回顾 → 成长」的完整采购闭环，**不是商城、不是纯 Memo**。

| 维度 | 一句话 |
|------|--------|
| 给谁 | 家庭采购者、独居年轻人、周末囤购/旅行打包场景 |
| 解决什么 | 漏买、乱买、超预算、到店想不起、采购无复盘 |
| 独特价值 | **情景动线清单 + 出门核对 + 补货周期 + 花费/分类洞察 + 采购主题/计划/打卡/成就** |
| 明确非什么 | 无商品浏览、下单、支付、广告聚合 |

**AppSpec.positioning 须同步改写**（当前仍写「轻量购物清单与备忘工具」，与 3.7 叙事冲突）。

## 2. 当前问题分析（基于 1.2.0 代码与审核反馈）

### 2.1 审核视角（3.7 同质化）

| 问题 | 根因 |
|------|------|
| 「还是清单+备忘」 | 首屏视觉与信息架构仍像「长 Scroll + 多个 Chip」，未形成独立产品记忆点 |
| 功能深度不足 | 计划/主题/成就已有，但**未在首屏形成「今日采购进度」主叙事** |
| 与市面 App 类似 | 清单勾选、备忘、提醒是品类标配；**差异化能力埋在中段或 Overlay，审核路径不易触达** |
| 层次不够 | 部分能力仍依赖「我的 → 工具入口」，未形成 Tab 级产品层级 |

### 2.2 产品架构问题

| # | 问题 |
|---|------|
| 1 | **首页信息密度不均**：Hero 仍是「添加物品」导向，非「今日采购进度 80%」主卡片 |
| 2 | **底栏「清单」语义窄**：内含备忘/模板，但 Tab 名未体现「采购执行中心」 |
| 3 | **成长 Tab 偏 Dashboard**：6 段 Chip 切换，缺少「采购日历」「月度回顾」等长期价值页 |
| 4 | **收藏体系分裂**：清单 `starred` 与 `FavoriteEntry` 两套，成就计数混合 |
| 5 | **搜索缺筛选维度**：有关键词，无状态/标签/时间/分类组合筛选 |
| 6 | **家庭场景浅**：`assignee` 字段存在，无「谁买、分工看板、按人筛选」 |
| 7 | **回顾不完整**：仅有「本周回顾」文案，无「本月/上月对比」 |
| 8 | **AppSpec 与实现脱节**：Tab 仍为 备忘；positioning 未体现工作台 |
| 9 | **脚手架残留**：`AIAssistantPage`/`DashboardPage` 等同仓未删，增加「模板感」风险 |
| 10 | **持续使用动机**：补货/路线/核对强，但**日历化「哪天采购、哪天超支」**未呈现 |

### 2.3 已有优势（必须保留并放大）

- 5 情景一键清单（超市动线/菜市场/补货/出行/囤购）
- 卖场路线 + 出门全屏核对
- 7 天补货提示
- 习惯诊断问卷 + 模板报告
- 常购库 / 历史再买 / 花费统计
- 1.1～1.2 成长层：计划、打卡、成就、时间轴、主题、收藏中心、分类洞察、物品可编辑详情

### 1.3.0 必做（8 项 · 有场景有闭环）

1. **首页「今日采购进度」主视觉** — 大 Progress + 计划/今日清单双数据源 + CTA「继续采购」
2. **底栏「清单」→「采购」** — ListsHub 增加第 4 段「情景」，与 SceneWorkbench 统一
3. **采购日历** — 月视图：打卡日、完成清单日、超预算日标记；点日期看当日动态
4. **高级搜索筛选** — 状态（待购/已购）、标签、分类、日期范围
5. **收藏夹分组** — 「清单方案 / 常购物品 / 备忘要点」三分组，统一取消收藏
6. **家庭分工看板** — 按 `assignee` 汇总待购；清单详情「分配给」Picker
7. **月度采购报告** — 实付/预估/Top 分类/完成清单数/打卡天数 + 复制分享
8. **操作联动链** — 勾选 → 首页 KPI + 计划进度 + 时间轴 + 成就 + 日历 同步（统一 `notifyDataChange` 广播）

### 1.4.0 增强（可选过审后迭代）

- 预算信封（周/月硬上限 + 超支提醒条）
- 常购库「最低库存」手动阈值 + 补货建议

- 服务卡片 Widget 深化（今日进度环）
- 导出 JSON 备份（剪贴板，无存储权限）

## 4. 页面结构（信息架构 · 四级层次）

```text
Index → MainTabPage（Stack 顶层 Overlay）
│
├─ Tab0 首页 · 采购工作台
│   ├─ 今日进度 Hero（一级）
│   ├─ KPI 四宫格 → 收藏/成长/洞察/日历（二级 Overlay）
│   ├─ 快捷操作 → 新建/情景/核对/搜索（三级动作）
│   ├─ 情景条 / 主题预览 / 今日清单 / 补货 / 看板（内容层）
│   └─ Overlay：Search / ItemDetail / PlanEditor / Verify / Aisle …
│
├─ Tab1 采购 · 执行中心（原 ListsHub 升级）
│   ├─ 段：清单 | 备忘 | 模板 | 情景
│   ├─ 列表 → ListDetailOverlay → ItemDetailOverlay（二→三级）
│   └─ CreateList / TemplateDetail / MemoForm
│
├─ Tab2 成长 · 计划与复盘
│   ├─ 段：数据 | 计划 | 打卡 | 成就 | 动态 | 回顾 | 主题 | 日历
│   ├─ PlanEditor / Topics / TopicDetail / CategoryInsight
│   └─ MonthlyReviewOverlay（新）
│
└─ Tab3 我的
    ├─ 统计摘要 / 工具入口 / 提醒 / 设置与隐私
    └─ Favorites / History / Habit / Library …
```

**禁止**：首页卡片点击仅 `switchTab` 无详情。  
**必须**：每条可点实体 → Hero 详情 + ≥1 CTA（已有 B12，保持）。

## 5. 底部导航方案

| 方案 | Tab | 理由 |
|------|-----|------|
| **推荐（1.3）** | 首页 \| **采购** \| 成长 \| 我的 | 「采购」涵盖清单+备忘+模板+情景，与「备忘 App」切割 |
| 备选 | 首页 \| 采购 \| **洞察** \| 我的 | 若成长 Tab 过重，把统计/报告独立为「洞察」 |

不采用 5 Tab（审核路径长、维护成本高）。  
**不恢复独立「备忘」Tab**（已并入采购中心，避免与市面双列表 App 同构）。

## 6. 数据模型（在现有 GrowthWire + LocalBundle 上扩展）

### 6.1 已有（保留）

- `ShoppingList` / `ShoppingItem` / `ShoppingMemoNote` / `FrequentItem`
- `ProcurementPlan` / `CheckInRecord` / `ActivityEvent` / `AchievementBadge`
- `ProcurementTopic` / `FavoriteEntry` / `GrowthSnapshot` / `WeeklyReview`

### 6.2 1.3 新增

```text
FavoriteFolder          // 收藏分组：list | item | memo
  id, name, sortOrder

MonthlyReview           // 月度回顾（由 StatsService 聚合生成，可缓存）
  monthKey, paidTotal, estTotal, checkedCount, listDone,
  checkInDays, topCategory, vsLastMonthPercent, summary

CalendarDayMark         // 日历标记（可由 events/checkIns 派生，可选持久化）
  dateKey, checkIn, listDoneCount, overBudget

SearchFilter            // 搜索条件（UI 态，不必持久化）
  keyword, status, tag, category, dateFrom, dateTo
```

### 6.3 关联关系

```text
ProcurementPlan ──linkedListIds──► ShoppingList[]
ProcurementTopic ──listIds/memoIds──► List / Memo
ShoppingItem ──assignee──► 家庭分工看板
ActivityEvent ──refId──► List | Item | Topic（已有 eventTarget）
FavoriteEntry ──folderId──► FavoriteFolder（1.3 可选分组）
```

**不引入**无法使用的空模型；月度/日历优先 **聚合派生**，减少持久化复杂度。

## 9. 用户使用闭环（审核可演示路径）

### 路径 A · 家庭周末采购（主路径 · 3 分钟）

1. 首页 → 点「周末囤购」情景 → 生成动线清单  
2. 清单详情 → 分配成员 → 卖场路线  
3. 出门核对 → 逐项勾选 → 自动打卡 + 时间轴  
4. 成长 → 本周回顾 / 月度报告  
5. 收藏中心 → 再买一次  

### 路径 B · 计划驱动（差异化）

1. 成长 → 编辑计划（20 件 / ¥500 / 关联 2 清单）  
2. 首页进度环随勾选上升 → 达成成就「计划达成」  

### 路径 C · 主题沉淀（个性化）

1. 采购主题 →「宝宝辅食」→ 关联 3 清单 + 2 备忘  
2. 搜索「辅食」→ 命中主题/物品/清单  

### 路径 D · 数据复盘（持续使用）

1. 分类洞察 → 本月报告 → 复制给家庭成员  

**一次操作，多处更新**：勾选物品 → 今日 KPI、计划进度、看板、时间轴、成就、日历标记。
