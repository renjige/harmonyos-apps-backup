# 球星风采 · App 丰富度升级方案

> 版本：v0.1 · 2026-08-31  
> 原则：**渐进式增强**（保留现有可用功能，补「记录→回顾→成长」闭环）  
> 约束：**0 新增系统权限** · 不申请相机/定位/健康等敏感能力

---

## 1. 产品重新定位

**一句话**  
从「球星资讯 + 关注列表」升级为 **「球迷个人工作台」** —— 围绕喜爱的运动员，完成 **发现 → 深读 → 对比 → 计划观赛 → 记录观点 → 回顾成长** 的全链路。

**与 3.7 饱和品类隔离**  
本 App **不是**记事本/日历/天气/计算器/聚合资讯类工具；核心是 **体育人物百科 + 个人球迷行为沉淀**（观赛计划、球探笔记、知识测验、对比研究），属于垂直体育工具，具备独立创作理念。

**目标用户场景**

| 场景 | 产品回应 |
|---|---|
| 赛前：今晚看谁 | 「观赛工作台」合并计划 + 提醒 + 倒计时 |
| 赛中/赛后：记录看法 | 球探笔记绑定赛事/球星，赛后一键写评 |
| 碎片学习：了解球员 | 知识挑战 + 错题回顾 + 累计正确率 |
| 研究型球迷：选星 | 双星对比可保存「研究对」 |
| 长期：我追过谁、看过几场 | 浏览足迹 + 时间轴 + 周/月回顾 |

## 2. 当前问题分析

### 2.1 结构层

| 问题 | 证据 |
|---|---|
| **浏览强、成长弱** | 5 Tab 以列表为主；无个人统计/成就/回顾页 |
| **功能做了但藏起来了** | `BrowseHistoryService` 写入有，首页 `showHistoryPanel` 无入口 |
| **入口重复、深度不足** | 专区 ≈ 球星+赛事筛选；首页赛程 ≈ 赛事 Tab；对比/测验一次性无沉淀 |
| **Overlay 单槽无栈** | 详情 → 写笔记会丢失来源详情上下文 |
| **文档与代码漂移** | AppSpec 仍 4 Tab；ia.md 4 Tab；demo-script 仍 AI/看板 |
| **脚手架残留** | `DashboardPage` / `AIAssistantPage` / `CoreBizPage` 未删 |

### 2.2 体验层（审核员视角 ≈ 3.5）

- 打开 App 像「内容目录 + 几个工具按钮」，**缺少「我的球迷档案」感**
- 用户操作（计划/笔记/测验）**不会随时间累积可见价值**
- 首页 KPI 是商户静态数（12 球星），**不是用户个人进度**

### 2.3 视觉层

- 首页有 Hero + 工具格，但 **缺「今日进度 / 个人数据四卡 / 最近活动」工作台层次**
- 深色模式 secondary 按钮对比度已修，但整体仍偏「列表 App」
- 部分赛事封面 key 共图（`StarMedia` 映射）

### 2.4 数据层

- 本地：`WatchPlan` / `ScoutNote` / `BrowseHistory` / `Reminder map` / Quiz **无持久化战绩**
- 云端：关注/提醒有 API，但 App **无「我的提醒」管理 UI**
- 各模块 **互不相连**（看完比赛不能从计划直达写笔记）

## 5. 信息架构与页面结构

### 5.1 底部导航（建议调整）

**现：** 首页 | 球星 | 赛事 | 关注 | 我的  

**建议：** **首页（工作台）| 发现 | 计划 | 成长 | 我的**

| Tab | 职责 | 由原页面合并/演进 |
|---|---|---|
| **首页** | 工作台：进度、四卡、快捷、最近活动 | `HomePage` 重构 |
| **发现** | 球星+赛事+搜索+专区入口（二级 Tab 或顶部分段） | `AthletesPage` + `EventsPage` 合并为 `DiscoverPage` |
| **计划** | 观赛清单 + 提醒管理 + 赛前倒计时 | `WatchPlanPage` 升格为 Tab 页 |
| **成长** | 时间轴 + 统计 + 成就 + 测验战绩 | **新** `GrowthPage` |
| **我的** | 账号、笔记入口、关注、设置 | `MinePage` 精简，迁出工具重复项 |

**保留为 Overlay（非 Tab）**

- 球星/赛事详情、对比、球探笔记编辑、知识挑战、项目专区、消息

**删除或隔离**

- `DashboardPage` / `AIAssistantPage` / `CoreBizPage` / `PrivacyPage`（编译保留或移 `_deprecated`）

### 5.2 页面层级（示例）


## 6. 数据模型（新增 / 扩展）

> 全部 **本地 Preferences** 为主；关注/提醒继续走平台 API。**不新增权限。**

### 6.1 新增模型（`models/FanGrowthModels.ets`）

```text
QuizRecord          // 单次测验：score, total, at, wrongIds[]
QuizStats           // 累计：bestScore, totalAttempts, accuracy

CompareSet          // id, athleteAId, athleteBId, sport, savedAt

WatchReview         // eventId, athleteId, rating, note, watchedAt  // 观赛后评

StreakState         // lastActiveDate, watchStreak, openStreak

Achievement         // id, title, unlockedAt, category

WeeklyReviewSnapshot // weekKey, watchedCount, notesCount, quizScore...

FanDashboardSnapshot // 聚合只读，由 FanStatsService 计算
```

### 6.2 扩展现有模型

```text
WatchPlanItem       + reviewId?, remindMinutes?
ScoutNote           + eventId?, linkedPlanId?, updatedAt
HistoryEntry        + sport?, coverKey?  // 时间轴展示 richer
```

### 6.3 服务层

| Service | 职责 |
|---|---|
| `FanStatsService` | 聚合 dashboard 四卡、完成率 |
| `QuizRecordService` | 测验落盘 + 错题 + 统计 |
| `CompareSetService` | 保存/加载对比组 |
| `WatchReviewService` | 观赛后评，链计划 |
| `AchievementService` | 规则判定 + 徽章墙 |
| `TimelineService` | 合并 History/Plan/Note/Quiz 按日排序 |
| `ReminderListService` | 读 ReminderService map，提供 UI 列表+取消 |

**联动规则（示例）**

- 标记已看 → 计划进度↑ + 弹「写观赛评？」+ streak 更新 + 成就检查  
- 保存笔记 → 时间轴 +1 + 首页「最近活动」+ 笔记计数  
- 测验结束 → 写 QuizRecord + 更新正确率 + 成就

## 9. 用户使用闭环

```text
浏览：发现 Tab 搜索 → 球星/赛事详情 Hero
  ↓
使用：对比研究夹 / 知识挑战 / 加入观赛计划 / 设提醒
  ↓
记录：标记已看 → 观赛后球探评 / 球探笔记
  ↓
管理：计划 Tab 清单 + 提醒列表；我的·笔记列表
  ↓
回顾：成长 Tab 时间轴 + 本周回顾
  ↓
成长：统计正确率/观赛完成率 + 徽章解锁
  ↓
（循环）首页工作台展示进度，驱动下次打开
```

**个性化：** 使用越久 → 时间轴越长、成就越多、工作台数字越大（**用户自己的数据**）。
