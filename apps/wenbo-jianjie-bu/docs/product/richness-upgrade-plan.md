# 见解簿 · App 丰富度升级方案（v1.0.3 规划）

> **状态**：方案稿 · 待确认后实施  
> **目标**：通过华为审核指南 **3.5（实质价值）** 与 **3.7（饱和品类差异化）**  
> **原则**：渐进式增强 · 不推倒重做 · **0 新增系统权限** · 保留 1.0.2 已有能力

---

## 〇、执行摘要

见解簿当前在审核眼中仍被归类为「**简单记录 + 整理**」，与鸿蒙应用市场 **3.7 饱和品类「记事本/笔记」** 高度重叠。  
1.0.2 已补「思考工坊」五入口，但 **信息架构仍像三个并列列表页**，缺少：

- 统一的 **工作台首屏**（今日进度、快捷动作、最近动态）
- **计划 / 目标 / 打卡** 与见解数据的显式关联
- **成就 / 成长** 可视化与联动反馈
- **全局活动流**（写、星标、验收判断、完成三问 → 一条时间轴）
- **「我的」个人空间**（设置、成就、导出、昵称目前藏在洞察齿轮里）

本方案 **不机械套用「首页｜探索｜计划｜记录｜我的」五 Tab**，也 **不增加第四个底栏 Tab**（遵守 `insight-book` 行业 Pack 与仓库差异化）。  
而是在 **记录｜整理｜洞察** 三 Tab 内做 **层级加深 + 数据联动 + 工作台化首屏**，形成「**思考产品**」而非「记事本换皮」。

## 1. 产品重新定位

| 维度 | 升级前（审核感知） | 升级后（对外表述） |
|------|-------------------|-------------------|
| 品类 | 本机笔记 / 备忘录 | **本机思考工作台 · 见解资产库** |
| 核心动词 | 记、整理、看统计 | **写判断 → 验收 → 复盘 → 成长** |
| 差异点 | 有时间线、标签 | **判断台账、思考框架、今日一问、随机回看、应验率** |
| 用户价值 | 存文字 | **把闪念变成可验证、可回顾、可积累的个人思考体系** |
| 一句话 | 智慧记录，沉淀洞见 | **写下见解，验收判断，看见自己的思考成长** |

**与 3.7 对抗话术**：不是「又一个记事本」，而是 **「判断驱动型思考工具」**——市面备忘录很少提供「待验证 / 应验 / 落空」闭环与周度三问复盘。

## 2. 当前项目分析（修改代码前）

### 2.1 产品定位（现状）

- 本地 Preferences + 沙箱，无网络、无登录墙、无 AI 对话。
- 实体：`InsightEntry`（见解）、`InsightNotebook`（笔记本）、标签字符串、用户 Profile。
- 创作理念：**见解 = 带结构的思考记录**（框架：闪念/判断/复盘/金句）。

### 2.2 已有功能（1.0.2）

| 模块 | 能力 |
|------|------|
| 记录 Tab | 时间线、搜索、全部/星标/置顶筛选、Hero、FAB 新建 |
| 整理 Tab | 标签云、笔记本（可新建）、月度时间轴、筛选列表 |
| 洞察 Tab | 思考工坊 5 项、热力图、近 7 日柱图、摘要、词云、统计卡 |
| 详情/编辑 | Hero、富文本、配图、复盘批注、关联见解、星标/置顶/判断验收 |
| 设置 | 昵称、深浅色、协议、撤回、导出 JSON、清缓存（入口在洞察齿轮） |

### 2.3 页面结构（现状）

```text
Index
└── MainTabPage (Stack)
    ├── Column [底栏 3 Tab]
    │   ├── RecordPage      ← 实际承担「首页」但无工作台密度
    │   ├── OrganizePage
    │   └── InsightPage
    └── Overlays
        ├── EntryDetailPane / EditorSheet
        ├── InsightToolHost（今日一问等）
        └── SettingsPage
```

### 2.4 底栏导航

`记录 | 整理 | 洞察` — 符合行业 Pack，**不建议改为 5 Tab**（易被判模板化且与差异化文档冲突）。

### 2.5 数据模型（现状）

- 单文件序列化：`InsightEntry`（含 starred/pinned/frameKind/reviewNote/verdict）
- 笔记本列表、Profile；**无**独立 Plan / Task / Achievement / Activity / CheckIn 表

### 2.6 跳转关系

- 列表 → 详情 → 编辑/删除/复盘 ✅  
- 工坊 → 写入见解 → 回记录 Tab ✅  
- **缺少**：首页快捷进工坊、计划进度、成就、统一「我的」、全局活动流

### 2.7 问题清单（对照审核与提示词 12 项）

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **首屏像「列表 App」**：Record 页以 Hero+筛选+时间线为主，缺今日进度/快捷四格/最近动态 | 高 |
| 2 | **无显式「计划层」**：本周三问、判断台账分散在工坊 Overlay，用户看不到「本周要完成什么」 | 高 |
| 3 | **打卡只有 streak 数字**：无「今日是否已写」「一键打卡说明」的轻交互 | 中 |
| 4 | **收藏体系弱**：星标/置顶/金句分散，无「我的收藏」统一入口与统计 | 中 |
| 5 | **无成就墙**：连续天有统计但无徽章解锁与 Toast 庆祝 | 中 |
| 6 | **无统一活动流**：写、星标、验收、三问完成未串成「成长时间轴」 | 中 |
| 7 | **「我的」缺失**：设置、昵称、成就、导出藏在洞察齿轮，不像完整产品 | 中 |
| 8 | **回顾分散**：今日要点/本周摘要/随机回看/三问未收拢为「回顾中心」 | 低 |
| 9 | **搜索缺维度**：仅关键词，缺框架/笔记本/时间/判断状态组合筛选 | 低 |
| 10 | **数据联动不足**：完成三问后洞察统计变、但首页工作台不联动 | 中 |
| 11 | **3.7 品类风险**：对外仍像「笔记三 Tab」，差异未在首屏 3 秒传达 | 高 |
| 12 | **视觉层次**：区块齐全但 Record 首屏信息密度低于商业工作台 | 中 |

### 2.8 功能重复检查

- 洞察页「本周回看」与工坊「本周三问」场景不同，保留但需在回顾中心聚合入口。  
- 记录筛选「星标」与整理标签列表部分重叠 → 收藏中心统一呈现，记录 Tab 保留快捷筛选。

### 2.9 视觉 Demo 感

- 品牌色与摄影 Hero 已具备；弱项是 **首屏缺「进度主卡片」** 与 **四指标数据带**。

### 2.10 持续使用理由（现状 vs 目标）

| 现状 | 目标 |
|------|------|
| 有事才打开写 | 每日一问 + 书写打卡 +  streak 成就驱动 |
| 写完即忘 | 判断台账催促「验收」 |
| 旧文难找 | 随机回看 + 活动流 + 收藏中心 |

## 4. 信息架构与页面结构

### 4.1 底栏方案（最终）

```text
记录（工作台 + 时间线） | 整理（内容中心） | 成长（原「洞察」升级命名）
```

- Tab 文案：**记录 → 记录**；**整理 → 整理**；**洞察 → 成长**（仅改 label，路由 index 不变，降低重构风险）。  
- **不设第 4 Tab**；「我的」为 **成长 Tab 顶栏头像入口 → MinePanel Overlay**（从 SettingsPage 拆出个人向内容）。

### 4.2 层级结构（每 Tab ≥3 层）

```text
【记录 Tab】
  L1  WorkbenchPage（首屏区块 + 时间线 List 下半）
  L2  EntryDetailPane / EditorSheet / AdvancedFilterSheet
  L3  详情内：复盘编辑、判断验收、关联跳转

【整理 Tab】
  L1  OrganizePage（三视图 + 排序）
  L2  OrganizeFilterPane（标签/本/月列表）
  L3  同 EntryDetailPane

【成长 Tab】
  L1  GrowthPage（工坊 + 看板 + 热力 + 词云）
  L2  InsightToolHost / ReviewCenterPane / AchievementWallPane / FavoritesHubPane
  L3  各工坊内写入 → 回 L1 刷新

【我的 Overlay】
  L1  MinePanel（昵称、徽章摘要、快捷设置）
  L2  SettingsPage（协议、导出、撤回）
```

## 5. 数据模型升级

### 5.1 扩展原则

- 新实体 **追加 Preferences key**，不破坏现有 `entries` / `notebooks` / `profile` 行格式。  
- 旧数据缺字段时使用默认值（verdict 已有先例）。

### 5.2 新增模型

```text
ThinkingPlanWeek
├── weekKey          // 2026-W35
├── goal1 / goal2 / goal3
├── done1 / done2 / done3
└── updatedAt

CheckInRecord
├── dateKey
├── note             // 可选一句打卡说明
└── entryCount       // 当日见解条数（冗余便于展示）

ActivityItem
├── id
├── type             // create | star | verdict | plan | checkin | achievement
├── refId            // 关联 entryId 等
├── title
├── dateKey
└── createdAt

AchievementState
├── unlockedIds[]    // 如 first_entry, streak_7, judge_10
└── lastEvalAt
```

### 5.3 InsightEntry（不破坏现有）

- 继续使用 `starred` / `pinned` / `verdict` / `frameKind`；收藏中心 **读聚合**，不改存储语义。

### 5.4 联动规则（一次操作，多处更新）

| 操作 | 联动 |
|------|------|
| 保存见解 | entries + Activity(create) + CheckIn 计数 + Achievement 评估 + Workbench 刷新 |
| 星标切换 | entries + Activity(star) + Favorites 计数 + Workbench |
| 判断验收 | verdict + Activity(verdict) + 成长看板应验率 |
| 完成周计划槽 | plan + Activity(plan) + 进度环 |
| 书写打卡 | checkin + Activity + streak 成就 |

## 6. 首页（记录 Tab）布局方案

自上而下 **五层**（遵守 `home-wireframe.md` 时间线主轴，在其上叠加工作台）：

```text
┌─────────────────────────────────────┐
│ 1. 品牌行：Logo + 见解簿 + 搜索 + 筛选图标 │
├─────────────────────────────────────┤
│ 2. 主视觉：今日思考进度（RingChart）      │
│    「本周计划 2/3 · 今日已写 ✓ · 连续 N 天」│
├─────────────────────────────────────┤
│ 3. 四指标：总见解 | 待验收 | 星标 | 本周写 │
├─────────────────────────────────────┤
│ 4. 快捷操作（横滑）：                    │
│    写见解 | 今日一问 | 随机回看 | 收藏 | 回顾 │
├─────────────────────────────────────┤
│ 5. 最近动态（3 条 Activity 摘要）→ 查看全部 │
├─────────────────────────────────────┤
│ 6. Hero 摄影条（保留，高度略减）          │
├─────────────────────────────────────┤
│ 7. 时间线（按日分组 · 现有 List）         │
└─────────────────────────────────────┘
                              [FAB +]
```

**禁止**：三列等宽 KPI 占满首屏（行业反模式）。进度环 + 四指标为 **第二层**，时间线仍为 **主内容区**。

## 8. 用户使用闭环

```text
打开 App
  → 工作台看见「今日一问 / 进度 / 待验收 2 条」
  → 点「今日一问」写判断
  → 自动打卡 + 活动流 + 可能解锁「首次思考」徽章
  → 回整理 Tab 按标签归档
  → 成长 Tab 看应验率与词云
  → 周末「本周三问」+ 勾选周计划
  → 随机回看旧判断写「现在怎么看」
  → 导出 JSON 备份
```

**浏览 → 使用 → 记录 → 管理 → 回顾 → 成长** 六步闭环完整。
