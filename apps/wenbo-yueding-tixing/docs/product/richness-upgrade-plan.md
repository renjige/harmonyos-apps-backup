# 《约定提醒》App 丰富度升级方案

> 目标：从「模板 + 简易记录」升级为「守约成长工作台」商业级产品  
> 原则：渐进式增强 · 不推倒重做 · 新增功能 0 个系统权限  
> 状态：**方案阶段（未开始编码）**

---

## 1. 产品重新定位

| 项 | 内容 |
|---|---|
| **原定位** | 轻量时间约定 + 提醒工具 |
| **新定位** | **守约成长工作台** — 围绕「承诺 → 执行 → 回顾 → 成长」的个人时间守约系统 |
| **一句话** | 不只记约定，更帮你守约、复盘、养成节奏 |
| **与系统日历差异** | 强调冲突检测、会前准备、计划目标、守约率、成就与时间轴，**不是**又一个日历/记事本 |
| **与 3.7 饱和品类差异** | 非纯日历/计时/记账；核心是「守约闭环 + 个人成长数据沉淀」 |

**创作理念（审核可述）**：  
用户对自己和他人做出的时间承诺，需要被记录、被提醒、被执行、被复盘。App 提供从「下一件倒计时」到「月度守约报告」的完整链路，让每次守约都计入个人成长。

## 2. 当前问题分析

### 2.1 审核员视角（50104 §3.5 拒审根因）

| 问题 | 现状证据 |
|---|---|
| 固定模板步骤罗列 | 8 个平台模板 + 创建向导，首页仍显「场景模板」区块，易被当成主内容 |
| 简易记录 | 核心仍是 AppointmentItem 增删改查，深度功能藏在 Overlay，首屏感知弱 |
| 场景有限 | 无收藏、无计划、无成就、无统一时间轴；用户数据沉淀感不足 |
| Demo 感 | 首页纵向堆叠 ToolEntry，缺「今日进度主视觉」与四象限数据卡 |
| 层次浅 | 多数能力为全屏 Overlay，缺独立 Tab 级「计划 / 成长」体系 |

### 2.2 现有能力盘点（保留，不删）

**已有且可用：**

- 4 Tab：首页 / 约定 / 日历 / 我的
- 约定 CRUD、冲突检测、推荐空档、重复续期
- 今日简报、找空档、逾期台、粘贴导入
- 场景中心、模板向导、智能整理、本周复盘、守约洞察
- 会前准备、到达打卡、改期、置顶、再约一次
- 桌面卡片、Agent 提醒、登录/游客、隐私合规
- 平台模板 API + 本地 Preferences 存储

**已有但「藏得太深」：**

- 守约洞察、智能整理、本周复盘 → 仅在首页/我的 ToolEntry
- 到达打卡 → 仅在详情页，未汇入成长数据
- 常用地点/相关人 → 仅在表单，无「我的联系人/地点库」管理页

**明确缺失（对比商业级要求）：**

| 缺失模块 | 说明 |
|---|---|
| 收藏体系 | 无 favorite 字段与收藏夹 |
| 计划系统 | 无 Plan + 子任务/关联约定 |
| 守约打卡 | 无「每日打开/完成约定」连续天数独立体系 |
| 时间轴 | 无统一 Activity 流水 |
| 成就系统 | 无徽章/成就墙 |
| 用户专题 | 无用户自建集合（如「本月会议」「亲子事项」） |
| 统一搜索 | 搜索仅在约定 Tab，不含计划/收藏/时间轴 |
| 标签体系 | 仅 scene 四维，无自定义 tag |
| 首页信息架构 | 无进度 Hero + 四数据卡 + 最近动态 |

### 2.3 脚手架残留（实施时清理引用，不删文件）

- `AIAssistantPage.ets` / `DashboardPage.ets` / `CoreBizPage.ets` — 未入主 Tab，避免误触
- `AppSpec.json` 仍含巡检/AI 脚手架描述 — 需与 store 文案同步

### 2.4 权限现状（保持不变）

- `INTERNET` + `PUBLISH_AGENT_REMINDER` — **不新增**任何权限

- ❌ 不做 LLM 对话主路径（保持 FeatureFlags.LLM_ENABLED=false）

## 6. 数据模型

### 6.1 扩展现有 `AppointmentItem`

```text
AppointmentItem（扩展字段）
├── favorite: boolean          # 收藏
├── tagIds: string[]           # 自定义标签
├── collectionIds: string[]    # 所属专题
├── planId: string             # 关联计划（可选）
├── checkedIn: boolean         # 已有
├── allDay / contactName / bufferMin  # 已有
└── activity 仍由 Service 写 Log，不冗余存储
```

### 6.2 新增本地模型（Preferences · `growth_local`）

```text
CommitmentPlan
├── id, title, description
├── targetCount: number        # 目标次数
├── doneCount: number          # 已完成（自动统计关联约定）
├── scene: string              # 可选场景
├── startDate, endDate
├── status: active|done|archived
├── linkedAppointmentIds: string[]
└── createdAt, updatedAt

UserCollection（专题）
├── id, title, iconKey, color
├── appointmentIds: string[]
└── sortOrder

UserTag
├── id, name, color

ActivityLog（时间轴）
├── id, type: create|complete|postpone|favorite|checkin|plan_done
├── refId, title, summary
├── occurredAt: ISO
└── scene

CheckInRecord
├── date: YYYY-MM-DD
├── done: boolean
└── note: string

AchievementState
├── key: streak_7|complete_50|zero_overdue_week|...
├── unlockedAt: ISO
└── progress: number           # 未解锁时的进度

FavoriteTemplate
├── templateId: string
└── savedAt
```

### 6.3 数据关联

```text
用户创建约定
  → AppointmentLocalStore
  → ActivityLog(create)
  → 若 planId 有值 → Plan.doneCount++
  → 若当日首次完成 → CheckInRecord + streak 重算
  → AchievementService.evaluate()
  → 首页四卡 + 成长 Tab 统计刷新

收藏约定
  → favorite=true + ActivityLog(favorite)
  → 约定 Tab「收藏」子 Tab + 我的收藏数
```

### 6.4 平台数据（不变）

- 模板仍走 `/biz/task-efficiency/tips`
- 登录用户约定可走 `/biz/task-efficiency/tasks`
- 用户活动（计划/收藏/成就/时间轴）**仅本地**，符合「我的数据」个性化

## 9. 用户使用闭环

```text
【新用户 · 首次 5 分钟】
引导页（3 屏）→ 首页空态
  → 粘贴导入 或 模板向导创建 2 条约定
  → 详情勾选会前准备 → 标记完成
  → 首页进度条变化 + 成长 Tab 出现首条时间轴 + 解锁「首次守约」成就

【日常 · 60 秒】
打开 App → 下一件倒计时 → 到达打卡 → 完成
  → 打卡连续天数 +1 → 计划进度更新

【周末 · 3 分钟】
成长 Tab → 本周回顾 → 导出剪贴板
  → 守约洞察 → 调整下周计划

【长期 · 30 天】
计划完成 → 成就墙增加徽章
  → 月度回顾 → 用户感知「数据在长大」
```

**一次操作，多处联动（示例）：**

完成 1 条约定 → 今日进度 / 四卡 / 计划进度 / 打卡 / 时间轴 / 成就 / 桌面卡片 同步更新。
